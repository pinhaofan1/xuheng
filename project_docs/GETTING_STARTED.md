# 叙衡浏览器版：运行与演示

本版包含创作工作台、离线规则审校、历史正文检索、AI 深度审校、人工反馈、任务与预算管理、托管恢复和报告导出。已在 Windows、Python 3.13.16、Node.js 24.19.0、npm 11.17.0 验证。浏览器交付编号为 0.9.0；后端基础版本号仍为 4.7.2。

## 当前电脑直接使用

从 http://127.0.0.1:8005/ 进入新版作品库，也可直接打开 http://127.0.0.1:8005/book/xuheng-demo/review/2?mode=ai 。本机已激活 DeepSeek，并保存了一次真实示例结果，无需重复配置或重复付费。服务关闭后，在项目目录运行 `start-xuheng.ps1`。

## 首次安装

在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt -c requirements-tested.txt
cd frontend
npm ci
npm run build
cd ..
.\start-xuheng.ps1 -Demo
```

发布压缩包已含 `frontend/dist`，仅运行时可省略 Node.js 安装和前端构建步骤。包内不含 Python、虚拟环境、模型密钥或用户数据库，仍需安装 Python 与后端依赖。首次安装火山 SDK 等依赖可能较慢。

如果系统策略不允许运行 `.ps1`，可以执行：

```powershell
.\.venv\Scripts\python.exe scripts/seed_xuheng_demo.py
$env:DISABLE_AUTO_DAEMON='1'
$env:EMBEDDING_SERVICE='openai'
.\.venv\Scripts\python.exe -m uvicorn interfaces.main:app --host 127.0.0.1 --port 8005
```

默认只绑定本机，打开服务时不自动启动托管执行进程；在工作台点击“启动全托管”后会按需启动并检查进程，启动失败会明确报错。示例初始化只增加数据，不覆盖已保存正文、配置或反馈；请在服务启动前执行。服务终端按 Ctrl+C 停止。

## 全托管的确认环节

在“章节创作”切换到“托管撰稿”，点击“启动全托管”，应用会请求模型生成规划。首次使用建议关闭弹窗中的“全自动模式”：宏观结构、幕级规划生成后会暂停，审阅后点击“再次确认 · 继续”才进入下一步。全书百分比按书稿进度计算，只有结构时仍可能是 0%。AI 调试面板开启时，还可手工审阅提示词与单次调用结果；普通界面会自动处理这些调用步骤。

开启“全自动模式”会跳过人工确认并持续调用模型，请设置合理的保护章数。保护值是累计托管章节数：已完成 1 章时，上限设为 2 会再写 1 章；上限可以小于全书目标，首次建议试写 1—2 章。绿灯只表示执行进程在线，不表示已经生成章节；执行进程断开会显示明确提示。长时间托管、断网和重启恢复仍在专项验证范围内。

如果界面更新后某个侧栏提示“此面板暂时无法加载”，先保存正在编辑的内容，再按 Ctrl+F5 刷新页面。构建会保留旧版哈希资源供已打开页面使用；异常时只显示手动刷新入口，不会自动刷新清掉草稿。

人物图中的节点应显示姓名，`ephemeral-…` 等是关联实体的内部 ID，不是向量。角色姓名会随出场记录保存，旧知识按同一本书的人物和地点档案解析名称；无法确认名称的旧实体在知识库中标记为“待命名人物”，暂不当作人物节点。人物图只投影可确认的人物关系，人物到地点、道具或概念的事实继续保留在知识库中。

## DeepSeek 本地配置

随时可以配置，无需等代码全部修改。在左侧工作区导航打开“AI 控制台”，进入 LLM 控制台，新建档案或导入 DeepSeek 预设：

| 项目 | 值 |
| --- | --- |
| 协议 | OpenAI 兼容 |
| Base URL | `https://api.deepseek.com` |
| 模型名 | `deepseek-flash`，或账户实际可用模型 |
| API Key | 只在本地表单填写 |
| Chat Completions | 开启 |
| 默认输出上限 | 8192 |

保存后点击“设为启用”，返回审校页重新加载。本次 AI 审校单独限制输出，默认 4096 Token。详见 [配置说明](DEEPSEEK_SETUP.md)。本地规则与 BM25 无需密钥；语义重排需要另配嵌入模型，可以先保持关闭。

## 五分钟演示

1. 打开示例第 2 章，在“审校设置”中核对并保存人物限制，点击“规则审校”。只检查已保存内容。
2. 点击“沈澜释放火球”，查看原文高亮和设定引用；多人同句的合法行为不会相互归属。
3. 确认、忽略、撤销后刷新，检查状态保留。假设句进入待确认项。
4. 切换“历史检索”，输入人物或事件并检索，只使用同作品前置章节。
5. 点击“AI 深度审校”观察进度；取消只请求停止后续处理，在途请求仍可能计费。
6. 核查摘要、引用与实际 Token 后处理。无效引用会被排除并警告，不能据此判断没有问题。
7. 在“运行历史”查看不同批次，通过“导出报告”下载 JSON。
8. 修改正文、设定或历史来源后重新加载，旧结果显示过期，需要重新检查。

已有真实结果可在 `?mode=ai` 下直接查看，不必为演示重复付费。标有 fixture 的测试截图来自隔离测试响应，不是真实模型结论。

## 正式作品与数据

首页创建作品、保存章节后，在作品卡片点击“审校”，或工作台上方点击“一致性审校 ↗”。审校页选择“审校设置”配置明确限制。明确限制独立于创作设定库，需要显式保存；“常用剑”不会被自动推断成“禁止射箭”。

凭据保存在本地配置中。默认数据库 `data/plotpilot.db` 沿用内部兼容路径，包含个人配置，请勿随源码分享。备份时停服后复制 `data/`。发布请使用打包脚本。

## 任务、用量与预算

“托管章节检查点”记录正文保存和章后步骤。保存成功需要从章节库读回一致正文；未能确认写入时会停止托管并保留生成稿，可点击“取回生成稿”下载 Markdown，不会覆盖当前章节。若队列稍后完成写入，恢复时按实际正文继续审计。

章后同步或模型请求失败时，先修复配置或网络，再从创作工作台手动恢复；正文版本匹配时复用已完成的审计步骤。正文修改后的旧记录不作为新正文的恢复依据。已完成每章审阅后恢复会前进，不反复停在同一节点。旧作品无检查点的章节不会自动批量补跑。

工作台右上角“更多工具 → 任务与用量”，或审校页左侧“任务与用量”，可查看审校任务、执行心跳和模型请求。明细每页 100 条，可以翻页或勾选“仅看待核对”；每日统计独立于明细分页，包含选定日期的全部请求。全托管的详细阶段仍在驾驶舱查看。

“章后处理任务”按作品、章节和正文哈希留存任务。保存接口先确认正文与任务记录，再进行分析；托管与旧版章后提取入口使用同一任务。API 服务启动后每 5 秒扫描可继续的队列；已运行任务以心跳判断，失去心跳 45 秒后识别中断，不把重启当作服务商请求已取消的证明。

已留存的分析模型结果可复用，图谱、伏笔、债务等本地写入和对应完成标记一起提交；重启后只处理未完成部分。未发送的模型请求仍可能产生新费用，继续受累计和每日预算限制。

若出现“需要确认”，先核对服务商用量，再点击“处理并恢复”，填写处理说明并确认是否重新请求未留存结果。确认只授权缺失结果的处理，已有结果继续复用，原请求预留不会自动释放，可在账单核对里处理。模型格式错误时默认恢复仍使用已存结果；确需重新请求，选择相应选项并填写依据，仅对尚无本地写入的未完成阶段更新请求，历史结果保留。正文修改或删除后旧任务不会继续写入。

章后任务、模型结果和本地写入完成标记保存在主库 `xh_aftermath_*` 表，费用预留仍在 `.operations.sqlite3`；两库都需备份。恢复扫描由浏览器版 API 服务负责；不自动为旧章节补建任务，不代表 F01 的完整真实模型长篇验收，跨正文版本的事实冲突处理另列 F06。

点击“设置作品预算”，可设置累计请求数、Token、金额上限；清空表示不限，0 表示阻止新的请求。默认不限，修改上限不会清空历史。费用估算需要填写与请求完全一致的模型名及人民币单价（元 / 百万 Token）；后补单价可覆盖原先未定价的记录，已有价格快照不会被重算。未定价历史尚未补齐时，金额预算会阻止新请求。

“每日限额”可以同时限制每日请求次数、Token 和费用。默认按 `Asia/Shanghai` 的本地零点划分日期，也可填写其他有效 IANA 时区，如 `UTC`。日期归属以请求发起时间为准，跨日完成或以后核对账单仍计回发起日；切换时区会重新划分每日统计，累计用量不变。选定旧日期时显示该日账目及当前预算设置，不回溯历史限额。每日预算拦截在下一当地零点失效，累计限额继续生效；停止的任务不会自动恢复。

请求明细中的“核对账单”允许填写服务商确认的输入、输出 Token、账单金额和核对依据。必须先确认服务商请求已经结束；不要填写 API Key。金额留空时按该请求保存的单价计算，无单价则费用保持未知。保存后替换该请求的预算计入值，同时更新累计及发起日统计，不修改原始请求，不重新调用模型或自动恢复任务。正在托管运行、生成或审校的作品，需要先停止任务再核对在途记录。

“查看核对”保留每次调整前后用量、金额差额、依据及编号；需要更正时继续追加新版本。重复提交同一次核对不增加第二条记录；旧窗口遇到其他核对更新会要求刷新。核对由使用者提供账单依据，不会自动登录服务商查询账单。金额继续按人民币记录，保留未知值；核对成功也不代表失败请求已经生成了完整正文。

请求发送前原子预留预算，收到用量后结算。OpenAI 兼容流式请求主动索取最终用量；正常完成且输入、输出计数有效时，账本和生成会话保存实际 token 数，不累加重复的用量快照。DeepSeek 官方聊天接口已实测，其他网关是否返回用量取决于其实现。

失败、超时、取消、断流或未返回有效最终用量时保留预留，显示用量待核对，不记为零、不自动重试。只返回文本的旧模型接口继续按预留计入；旧记录不追溯重算。预留输入按字节和消息余量估计，输出按请求上限估计；它不是服务商分词器，不能保证服务商账单不会超过估算。金额仍按自填单价估算，缓存与阶梯计价等以服务商账单为准。记录仅覆盖本版本启用后已关联作品的接入路径，无作品归属的连通性测试不计入。

服务重启后，未完成的审校任务标记“已中断”，不会自动重新请求。已经保存结果的任务可恢复结果关联；“重新发起”需要确认，创建关联的新记录，保持原记录。正文已变化时返回章节重新审校；对同一旧任务重复提交不会再创建第二个子任务。预算拦截后托管会停止，调整预算后需手动恢复。

任务和预算保存在主数据库旁的同名 `.operations.sqlite3` 中；备份需同时包含主数据库与运行记录库，运行中使用 SQLite 一致性备份，或先停止服务再复制两者。当前只支持单个本地 API 进程，不要以多个 worker 同时调度同一数据目录。

离线验证：`.\.venv\Scripts\python.exe scripts/verify_bounded_writing.py`。加 `--real` 会使用本地激活档案发出最多两次、各 1024 输出 Token 的真实请求，独立测试库位于 `.validation`。检查预置规划的两章生成、保存与预算拦截，关闭额外章后 AI 调用，不代表完整长篇托管。


## 0.4.0 检索与事实配置

左侧“检索模型”统一配置 Embedding 与 Reranker；与原嵌入配置共用本地 Key，界面不会返回 Key 明文。推荐接口 `https://api.siliconflow.cn/v1`，模型为 `Qwen/Qwen3-Embedding-4B` 和 `Qwen/Qwen3-Reranker-4B`，向量维度 1024。保存后可测试两个模型。

审校设置中的历史检索模式可选“关键词”“关键词＋语义召回”“混合召回＋模型重排”。后两种会为同作品前章建立向量缓存；范围仍是最近 100 章、50 万字符。输出报告记录实际检索调用与服务商返回的 Token，未知用量保持未知。

“人物设定”支持通用事实，如伤势、身份、年龄。点击“从作品人物库导入草稿”后核对并保存，不会把常用武器推断成禁止其他武器。通用事实由 AI 检查，离线规则仍只检查明确动作约束。

真实联调示例：http://127.0.0.1:8005/book/xuheng-integration-demo/review/2?mode=ai 。它是自编虚构样例，不是独立质量评测。

安装依赖并构建后，可双击 `start-xuheng.cmd` 启动，服务就绪后自动打开浏览器。此入口不是原生桌面安装包，不包含 Python 解释器。
