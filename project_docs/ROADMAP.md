# 后续完善清单

当前基线为 0.4.0：本地全量单元测试 1629 项通过、7 项跳过，4 项浏览器测试通过；已真实联调混合检索、证据审校、受控单章请求，以及全托管宏观规划、首幕规划、首章保存、章后流程和保护章数自动停止。远端 CI 结果以 GitHub Actions 为准。

## 优先级一：适合简历展示和面试验证

1. 建立真实长篇评测集。采用可公开使用的文本，覆盖伤势、时间线、物品转移、人物关系和伏笔；由独立人工标注后统计召回率、误报率及引用正确率。现有自编样例和一次联调不代表真实准确率。
2. 验证长时间托管与恢复。在独立测试作品上限制章节数与预算，验证暂停、断网、限流、进程重启及续写；当前进程内 AI 审校任务重启后不会恢复。
3. 完善任务与费用管理。增加持久化任务状态、明确重试策略、单次及作品级预算；覆盖 LLM、Embedding 和 Reranker 的累计用量。

## 优先级二：完整应用体验

4. 扩展检索规模。当前限于最近 100 章、50 万字符；需要增量索引、删除清理、后台建索引进度、分层历史召回，以及更长作品的性能测试。
5. 打磨创作流程。补充更完整的新手示例、人物事实同步策略、多人同名处理、错误恢复和长章节/大图谱的界面体验。
6. 统一文档和 CI。部分上游历史文档、发行脚本及内部标识仍沿用原项目；需要逐步补齐本项目的部署说明及跨平台验证，保留来源与许可。

## 按实际交付目标开展

7. 原生 Windows 安装包。需要 Rust/cargo、MSVC C++ 构建工具及 Tauri 打包验证，配置本项目标识、资源、签名与更新渠道；现有双击脚本仍依赖 Python 环境。
8. 公网部署。当前按本机工具交付；若公开服务，需要账户和作品权限、密钥管理、服务端任务队列、备份恢复及部署隔离。
9. 在线社区。现有入口依赖上游外部服务，当前没有自建社区后端；这不是展示本地审校核心能力的前置条件。

建议先完成前三项，再根据实际需要选择桌面或公网交付。简历可使用已有实现和验证结果，不应写入未完成的用户量、准确率、并发或长期运行指标。
