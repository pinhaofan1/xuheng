# 叙衡 0.7.0 · 流式请求真实用量结算

日期：2026-11-05。对应进度项：F04。

## 改动

- 增加逐请求的流式事件，分别传递正文增量与最终用量快照；保留原有字符串流接口。用量不保存在共享模型实例上，避免并发、多作品和嵌套调用串账。
- OpenAI 兼容 Chat Completions 请求发送 `stream_options.include_usage=true`，接收空 `choices` 的用量尾帧。Responses 接收 `response.completed` 的用量；重复快照替换，不累加。
- 只有正常结束、输入与输出均为非负整数、总数若提供则一致时，才按实际 token 数结算并保存到运行账本、调用追踪及生成会话。服务商明确返回的零计数有效。
- 缺少或无效的最终用量继续保留预留额度。异常、断流、取消不记为零、不自动重试或切换接口；已收正文保留在生成会话，终止状态可以持久化读回。
- 托管生成和审阅面板后台生成均接入用量事件；停止托管或取消生成时主动关闭上游流。相同作品的嵌套范围继承既有账本，避免覆盖外层已指定的账本路径。

## 验证

全量单元测试 **1727 项通过、7 项跳过**；**11 项浏览器场景通过**；前端类型检查与生产构建通过。

新增 27 项专项测试位于 [test_stream_usage_accounting.py](../tests/unit/infrastructure/ai/test_stream_usage_accounting.py)，使用真实 OpenAI SDK 与模拟 HTTP/SSE，不依赖付费模型，覆盖：

- 正常用量尾帧、重复快照、有效零值、最终用量缺失、提前出现的用量、缺失字段、负数和总数矛盾；解析器拒绝布尔值、字符串和小数。
- 正常结算释放多余预留后允许下一次预算内请求；金额按请求时保存的单价快照计算。
- 未收到结束标记、读取失败和 HTTP 429；每次只发一个物理请求。
- 主动停止及任务取消时立即关闭上游，账本保留预留；生成会话保存部分正文与取消状态。
- 两本书并发共享模型实例、嵌套流调用、只返回字符串的旧接口，以及配置附加参数不能关闭用量请求或修改已存配置。
- Responses 正常完成、失败、不完整与缺失结束事件。
- 实际 SQLite 会话存取；审阅面板后台生成的用量与取消状态持久化。

使用本机已配置的 **DeepSeek 官方接口 / deepseek-flash** 完成一次真实流式请求，输出上限 128 token：正文为 `stream ok`，服务商返回输入 **14**、输出 **2** 个 token；独立账本为 completed、1 次调用、0 次未知用量。该检查不写入用户小说，不代表全部网关或长篇托管长跑。

浏览器回归覆盖编辑保存、审校、人物图、任务预算、检查点和辅助面板。本地现有作品页面另做只读检查；服务重启前核对无正在生成的会话与审校任务，不启动用户作品的托管生成。

## 使用与边界

刷新本地页面，在“更多工具 → 任务与用量”查看新请求记录。支持最终用量的正常流式请求现在显示实际 token；旧未知记录不追溯重算。缺少最终用量仍显示待核对并保留预留。

金额按自填单价估算，不等同于服务商最终账单；缓存优惠、推理计数口径与阶梯计价等需按服务商核对。尚未返回计数的中断请求可能已被服务商计费，不能当作免费请求。

协议依据：[OpenAI Chat 流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)、[Responses 流式事件](https://developers.openai.com/api/reference/resources/responses/streaming-events)。Chat 的最终用量帧允许空 choices；中断时可能收不到该帧，因此缺失值保持未知。
