# 叙衡 0.4.0 交付记录

## 2026-11-04 全托管启动修复

- 启动脚本默认不自动拉起执行进程；显式点击全托管启动时会按需启动，并等待子进程完成依赖初始化。失败返回 503，不再返回虚假的运行成功。
- 启动、恢复须先保存任务，再发布运行状态；前端等待接口确认后再提示成功。
- 运行灯检查真实进程和心跳，不再把共享内存数据或 `running` 标记当成存活证明；进程未连接时明确报错。长模型请求期间，心跳由独立线程维护。
- 实际作品宏观规划会话成功返回 16,316 字符，结果提交成功，数据库生成 2 部、4 卷、17 幕，随后停在人工审阅节点。该检查覆盖全托管宏观规划链路，不代表 150 章连写已验证。
- 后续验证首幕生成 6 个章节规划，首章正文保存 2192 字符，章后流程结束后达到 1 章保护值并自动停止，第 2 章正文仍为空。修复新写作管线未检查保护章数、状态接口固定返回 9999、数据库旧 RUNNING 标记覆盖本地停止、统计读取忽略最新缓存的问题；保护值与完稿/字数现在随持久化、共享状态和接口一致传递。
- 本地全量单元测试 1629 通过、7 跳过；4 项浏览器场景通过，新增“执行进程断开”和“启动失败不得提前宣布成功”检查，以及章节保护上限阻止下一次付费请求、停止状态合并和章节统计的回归检查。

日期：2026-11-04。继续保留上游版权和完整许可证；本版是基于原创作工作台的审校扩展。
